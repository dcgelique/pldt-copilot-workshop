Scenario: Build an IT Platform Support Agent that answers from approved sources, applies a reusable troubleshooting method and prepares a support-request summary when self-service troubleshooting does not resolve the issue.

Prerequisites

Module 1

Explore Copilot Studio and agent harnesses

A harness is the runtime architecture behind an agent or workflow. For this workshop, use the GitHub Copilot harness because the scenario involves reasoning across instructions, knowledge, a reusable skill and a workflow.

HarnessWorkshop decision lens
GitHub Copilot harnessReasoning-heavy, multi-step work using knowledge and tools.
Standard harnessRule-based and predictable topics, paths or flows.
Copilot chat harnessExtend Microsoft Copilot Chat with organisational knowledge.

Exercise: select a harness

For each scenario, decide which harness appears most appropriate and explain the reason: employee policy Q&A in Copilot Chat; fixed password-reset conversation; multi-step IT issue diagnosis and escalation.

Module 2

Create an instruction-driven agent

1

Create the agent

Open Copilot Studio, select the dedicated environment, then create a new agent powered by the GitHub Copilot harness. Name it IT Platform Support Agent – [Initials].

2

Write effective instructions

You are an IT Platform Support Agent for enterprise employees. GOAL Help users understand and troubleshoot common platform issues using approved knowledge. If the issue remains unresolved, prepare a support-request summary by using the available workflow. OPERATING RULES 1. Identify the platform and the user's intended outcome. 2. Use available knowledge before giving organisation-specific guidance. 3. Give concise, numbered troubleshooting steps. 4. Do not invent policy, system status, URLs, ownership or procedures. 5. If information is unavailable, say what cannot be verified. 6. Before escalation, collect platform, issue description, business impact and troubleshooting already attempted. 7. Use the IT Troubleshooting Method skill when diagnosing an issue. 8. Use the workflow only after the user agrees to prepare a request. RESPONSE FORMAT Issue summary Recommended steps Result to verify Escalation path, when needed

Module 3 extension

Create, add and test a reusable skill

Create a skill called IT Troubleshooting Method and use this Markdown content:

# IT Troubleshooting Method Use this skill when a user reports that an IT platform, application, account or connection is not working as expected. ## Method 1. Restate the problem in one sentence. 2. Ask only for missing context needed to diagnose the issue. 3. Check the available approved knowledge. 4. Recommend no more than four low-risk troubleshooting steps. 5. Ask the user to verify the result. 6. If unresolved, summarise the issue, impact and steps attempted, then offer escalation. ## Boundaries - Do not claim that an outage exists unless an approved source confirms it. - Do not request passwords, secrets, tokens or sensitive authentication data. - Do not run an action unless the user understands what will happen.

Test: I can sign in to the Finance Portal, but the page stays blank. Refine the skill description or agent instructions if the expected behaviour is not selected.

Module 4

Automate an agent task with a workflow

In this exercise, you will create a workflow that the agent can call after troubleshooting is unsuccessful. The workflow accepts structured issue information, composes a support-request summary, and returns that summary to the agent for the user's review.

Expected outcome: The agent gathers the required information, asks the user before preparing the request, invokes the workflow, and displays the returned summary.

Exercise 4.1 — Plan the workflow contract

Before opening the designer, define the data that crosses the boundary between the agent and workflow.

DirectionNameTypePurposeExample
InputPlatformTextIdentifies the affected application or service.Finance Portal
InputIssueDescriptionTextProvides a concise statement of the problem.Blank page after sign-in
InputBusinessImpactTextExplains the effect on the user's work.Daily reconciliation is blocked
InputStepsAttemptedTextRecords the troubleshooting already completed.Signed out, reopened browser and tested a private window
OutputSupportRequestSummaryTextReturns a structured summary to the agent.Prepared request for service desk review

Exercise 4.2 — Create the workflow from the agent

  1. Open the Build tab of your IT Platform Support Agent.
  2. In the components panel, select Tools.
  3. In Add a tool, select Add, and then select Workflow.
  4. When the workflow designer opens, confirm the canvas contains When an agent calls the flow and Respond to the agent.
  5. Rename the workflow to Prepare IT Support Request Summary – [Initials].
If the expected nodes are missing: Return to the agent's Build tab and start the workflow through Tools → Add → Workflow so the workflow is created for agent invocation.

Exercise 4.3 — Configure the agent inputs

  1. Select When an agent calls the flow.
  2. Add a text input named Platform. Describe it as the affected platform or application.
  3. Add a text input named IssueDescription. Describe it as a concise statement of the issue.
  4. Add a text input named BusinessImpact. Describe it as the effect on the user's work or business process.
  5. Add a text input named StepsAttempted. Describe it as the troubleshooting already completed.
  6. Confirm that all four inputs are required for this workshop exercise.
Why descriptions matter: Clear input names and descriptions help the agent supply the correct information when it invokes the workflow.

Exercise 4.4 — Compose the support-request summary

  1. Between the trigger and response nodes, select the option to add an action.
  2. Add a text-composition action available in the workflow designer.
  3. Rename the action to Compose support request summary.
  4. Build the summary below and insert the corresponding input tokens from When an agent calls the flow.
SUPPORT REQUEST Platform: [Platform] Issue: [IssueDescription] Business impact: [BusinessImpact] Troubleshooting attempted: [StepsAttempted] Status: Prepared for service desk review

Replace each bracketed placeholder with the matching dynamic-content token. Do not leave the bracketed sample text as static content.

Exercise 4.5 — Return the result to the agent

  1. Select Respond to the agent.
  2. Add a text output named SupportRequestSummary.
  3. For its value, insert the output from Compose support request summary.
  4. Select Save, resolve any validation errors, and then select Publish.
Do not continue until publishing succeeds. An unpublished workflow might not be ready for the agent to use.

Exercise 4.6 — Verify and describe the workflow tool

  1. Return to the agent's Build tab.
  2. In Tools, confirm that Prepare IT Support Request Summary – [Initials] appears.
  3. Open the tool configuration and review its name and description.
  4. Use the following tool description:
Prepares a structured IT support-request summary after troubleshooting is unsuccessful and the user agrees to escalation. Use this workflow only after collecting the platform, issue description, business impact, and troubleshooting already attempted.

If the agent instructions do not already include an action guardrail, add:

Before using the support-request workflow, summarise the information collected and ask the user to confirm that a support-request summary should be prepared.

Exercise 4.7 — Test the workflow in Preview

  1. Open the Preview tab.
  2. Enter the test prompt below.
  3. If the agent asks for missing details, answer the questions using the sample values in the workflow contract.
  4. Confirm that the agent asks before invoking the workflow.
  5. Review the returned support-request summary.
I still cannot access the Finance Portal after trying the recommended steps. This prevents today's reconciliation. Please prepare a support request.

Exercise 4.8 — Inspect the activity trace

  1. Open the activity trace for the test conversation.
  2. Confirm which workflow tool was invoked.
  3. Review the arguments passed for Platform, IssueDescription, BusinessImpact and StepsAttempted.
  4. Review the value returned in SupportRequestSummary.
  5. Compare the trace with the final response shown to the user.

Exercise 4.9 — Troubleshoot tool selection

Observed issueWhat to review
The workflow does not appear in Tools.Confirm the workflow was saved and published, then return to the agent's Build tab.
The agent does not invoke the workflow.Refine the workflow name, tool description, and agent instructions so the invocation condition is explicit.
The workflow receives empty or incorrect values.Review the trigger input names and descriptions, then inspect the activity-trace arguments.
The workflow runs before user confirmation.Strengthen the agent instruction that requires confirmation before using the tool.
The returned summary is incomplete.Confirm that the compose action uses all four trigger inputs and that the response output uses the compose result.
Module 5

Evaluate, publish and manage

Evaluation goal: Turn the informal prompts you used in Preview into a repeatable test set with representative inputs and expected outcomes. Use the results to identify whether a problem belongs to instructions, grounding, capability selection, workflow behaviour, or another component.

Exercise 5.1 — Complete a final Preview check

  1. Open your IT Platform Support Agent.
  2. Open Preview.
  3. Run one known-answer prompt and one workflow prompt from the tests below.
  4. Confirm the agent is in a stable state before creating the evaluation. If either test clearly fails, fix that issue first so the evaluation represents the version you intend to assess.
My VPN connects, but I cannot access internal applications. What should I try?
I still cannot access the Finance Portal after troubleshooting. This blocks today's reconciliation. Please prepare a support request.

Exercise 5.2 — Open Evaluate and create a test set

  1. From the agent, open the Evaluate tab.
  2. Start a new evaluation or test set using the creation option shown in your environment.
  3. Name the test set IT Support Agent – Core Evaluation – [Initials].
  4. Add representative test cases rather than only repeating one successful prompt.
  5. For every test case, provide the user input and the expected outcome available in the evaluation experience.
UI note: Microsoft Learn defines the outcome as creating representative test cases with expected outcomes and reviewing evaluation results. Preview features and labels can change, so follow the equivalent controls shown in your workshop tenant.

Exercise 5.3 — Build the core evaluation cases

Create the following cases. The expected outcome describes the behaviour you are testing; it is intentionally more specific than a generic “good answer”.

Exercise 5.4 — Run the evaluation

  1. Save the evaluation or test set.
  2. Use the available option to run the evaluation against the current agent.
  3. Stay on the evaluation results view when the run completes.
  4. Review the overall result, then inspect individual test cases. Do not rely only on an aggregate indicator.
  5. Pay particular attention to cases involving grounding, capability/tool selection, and the workflow because they exercise multiple agent components.

Exercise 5.5 — Diagnose a failed case

For each failed or weak result, classify the problem before editing the agent.

SymptomMost likely area to inspect firstWorkshop refinement
Answer ignores a required format or boundary.InstructionsMake the relevant rule clearer and less ambiguous.
Answer uses the wrong or incomplete internal information.Knowledge / groundingReview the intended source, content, description, and conflicting sources.
Troubleshooting method is inconsistent.Skill or instructionsReview the IT Troubleshooting Method and its description.
Agent does not choose the support workflow.Capability/tool selectionReview the workflow tool name, description, required inputs, and invocation rule.
Workflow runs but the returned summary is wrong.WorkflowInspect the workflow arguments, compose step, and returned output.
Source conflict is hidden.Instructions + knowledge governanceStrengthen the conflict-handling rule and review source authority.
Use the activity trace when useful: For a failed interactive test, inspect which knowledge, skill, or tool was selected and what arguments were passed. This helps you change the correct component rather than rewriting everything.

Exercise 5.6 — Refine and rerun

  1. Choose one failed or weak evaluation case.
  2. Make one targeted change to the relevant component.
  3. Save the agent.
  4. Run Preview for a quick check.
  5. Rerun the evaluation set.
  6. Compare the affected test-case result with the previous run and verify that the change did not introduce an obvious regression in the other cases.

Exercise 5.7 — Record publish readiness

Before moving to publication, record the status of these checks:

Readiness checkReady when…
Core support answersRepresentative support cases meet the expected outcomes.
GroundingKnown-answer cases use the intended knowledge and unsupported questions remain bounded.
Capability selectionThe workflow is selected only for the intended escalation scenario.
Workflow behaviourRequired inputs, confirmation, invocation, and returned summary behave as designed.
Security boundaryThe agent does not request passwords, codes, tokens, or secrets.
PermissionsKnowledge and tools use only approved workshop connections and sources.

Publish readiness

Do not publish unless the facilitator confirms the workshop environment and channel are approved. Before publication, review evaluation results, access, source permissions and workflow connections.

Monitor and govern

In Monitor, review available production health, outcomes, reactions, sessions and credit usage after the published agent is used. Record improvements against the component that needs change: instruction, knowledge, skill, tool or workflow.
